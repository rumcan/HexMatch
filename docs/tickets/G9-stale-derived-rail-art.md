## Root cause

Two committed PNGs do not match what `tools/make-derived-art.mjs` produces
today. They were generated by an older revision of the script and never
regenerated:

| file | committed | regenerated |
|------|-----------|-------------|
| `src/iso/kenny/derived/rail_0101.png` | 12 791 B | 2 272 B |
| `src/iso/kenny/derived/rail_1010.png` | 12 662 B | 2 284 B |

The stale `rail_0101` carries dark rail pixels at the **SE** arm midpoint
(125 dark pixels in the test's 21×11 window), which is an unset arm for mask
`0101` (NE+SW) — exactly the 90°-off class of bug the test exists to catch.

## Fix (verified)

```bash
node tools/make-derived-art.mjs   # rewrites rail_*.png, crossing, highlight
npm run slice-atlas               # repack (verified: atlas is byte-identical,
                                  #          assets/iso-atlas/ shows no diff)
npm test                          # → 12/12 pixel tests pass, 333/333 green
```

I ran all three while investigating and confirmed the suite goes green and the
packed atlas does **not** change (`git status assets/iso-atlas/` empty) — the
staleness is confined to the two source PNGs. I then reverted the working tree
so this PR stays on its own ticket, per the backlog's one-ticket-per-PR rule
and its "don't touch the art pipeline" instruction.

## Acceptance

1. `node tools/make-derived-art.mjs` produces **no** diff against the committed
   `src/iso/kenny/derived/*.png` (the derived art is a build output; it must be
   in sync with its generator).
2. `npm test` → 333/333, including `K2 road masks > rail masks carry rails on
   their set arms`.

4. Optional but recommended: a test or CI step that regenerates the derived art
   and fails when the output differs from what is committed, so this class of
   drift cannot reappear silently.
